Patterns that carry over.

What SpaceWorks 0.12.0 settled. Every Space Works app copies these rather than reinventing them.

Ask areas, not modules

Setup asks which areas a space runs. What is off is hidden everywhere. Never show internal words.

Settings by intent

Seven groups (Space, People, Areas, Money, Communication, Integrations, Administration), search over all, one line of help per row.

Views per role

Each area manager sees their whole area; the Space Manager sees it all, grouped by area with totals.

Five states, not one

Design loading, empty, no results, offline and error-with-retry for every list, in both themes.

Shared pager and confirm

Every list uses the one pager; every destructive action a real confirm dialog with a close button.

Dialogs that stay put

Close on the backdrop only if press and release both land there, so a text selection dragged out never closes it.

Scroll that remembers

Back restores the position; a new page starts at the top. Focus moves only on a real page change.

Bulk actions

A sticky bar appears with the count and a “Clear selection” action.

Search knows synonyms

The palette matches both names of a page: Home and dashboard, Notifications and Inbox.

Colours that fix themselves

A space picks two colours; the product shows where they apply, checks both themes and offers a one-click fix instead of refusing.

Simple and advanced

Card Studio offers Quick and Advanced modes on the same document, and shows the photo consent notice where the photo is taken.

Motion with a fallback

A scroll story always has a static version for reduced motion and phones.

Product rules, in short.

What every Space Works product follows, from the main app to the phone apps.

Areas

Everything optional is an area with one registry key. Off means gone everywhere. Switching off keeps data; purge is a separate, deliberate step.

Role views

Permissions are actions, not role names. Each person sees only what their role holds; the server refuses too.

One space, one scope

Every record belongs to one space and every query is scoped. Public pages never show locations, QR codes or evidence.

Audit trail

Every state change writes an append-only audit entry. Evidence is immutable. No issue without a scan and a photo.

Money

Record the debt first, add a payment rail second. Minor units with currency, never floats. Idempotent, and the ledger is permanent.

Analytics

Counts only: how many, by channel and day, never who. Web, iOS, Android and API clients are tagged.

API

Every endpoint in OpenAPI with typed errors. The same authority on web and native tokens; 429 with Retry-After.

Code size

About 200 lines per file, 300 at most. Split by responsibility behind a thin barrel; split first, then add.

Install in one line

One command asks every question first, changes nothing until you confirm, and runs again to update.

Hosted or hybrid

One space, many spaces, or a platform. The website can live here or elsewhere with this as the API.

Words

Every string translated as a whole sentence with real plurals. Error codes stay stable; messages translate.

Tests

Test what people can observe. The baseline is zero failures, and no test is ever deleted.

The accessibility floor.

Not a target to aim at. The level nothing ships below, in light and dark, with no allow-list.

4.5 : 1

Text against every surface it can sit on, including hover and soft fills.

3 : 1

Icons, control edges (outline) and focus rings.

44 px

Every control's height. One checkbox and radio size.

2 + 2

Focus ring: 2 px wide, 2 px offset, opaque focus token.

  • A word for every status. Colour is never the only cue; charts add a dash per series.
  • No translucent text, and never focus:outline-none.
  • Everything works from the keyboard. The skip link target always renders; collapsed content is unmounted.
  • Accessible names match the visible label. Icon-only buttons are named.
  • Reduced motion is honoured everywhere, with a still version that carries the same information.
  • Loaders speak: role="status" with a polite label; busy buttons set aria-busy; error toasts are alerts.
  • Both themes are tested: axe in component tests, and a browser suite (WCAG 2.1 AA, light and dark journeys) fails the build on any violation.
  • Tenant colours are proven readable in both themes before they render.
