# Scroll reveal and pinned hero

The landing page's scroll story: the pinned hero sequence (copy lifts away, the real console rises, zooms through its surface and the overview settles in, all in one sticky scene), the handover steps beside a sticky record, and reveal-on-scroll blocks that arrive once. The default rules are the static page, which is what reduced motion, phones and browsers without JavaScript get.

Open [`demo.html`](demo.html) in a browser (it links `../../tokens/tokens.css`) and use "Toggle dark" to check both themes.

## Files

| File | What it is |
|---|---|
| `scroll-reveal.css` | The whole landing scroll stylesheet, verbatim (static page by default; pinned and reveal states only when the hooks mark the page). |
| `scroll-reveal.js` | Framework-free port of the hooks: `initReveal` (IntersectionObserver, once) and `initSequence` (smoothstep scroll mapping with the real ranges). The React originals are in `react/`. |
| `demo.html` | A standalone page with the live animation in light and dark, replayable. |
| `react/` | Copies of the real app files (see `react/README.md` for the imports to replace). |
| `previews/` | Animated WebP and GIF previews, light and dark (regenerated by `scripts/make-previews.mjs`). |

## Where the app uses it

- Pinned hero: `features/hub/landing/HeroSection.tsx`, `useScrollSequence.ts` (768 px and wider, when the copy, console and overview fit).
- Handover steps beside a sticky record: `HandoverScrolly.tsx` (1024 px wide and 640 px tall or more).
- Reveal on scroll: `data-reveal` blocks in `StorySections.tsx`, `AreasSection.tsx`, `FaqSection.tsx` and the rest of the landing page, via `useInView.ts‬ (`useRevealOnScroll`).
- Styles: `features/hub/landing/landing-scroll.css`.

## Why

Scrolling walks the visitor from the promise to the real console to the overview in one scene, so the product is understood by looking at it, not by reading about it. The handover record changes as each step reaches the middle, showing the evidence trail forming. Reveals pace a long page without hiding content.

## Timing, easing and distance

| Part | Value |
|---|---|
| Pinned scene | 300 svh tall, scroll-driven transform and opacity (no timing), `will-change` only while moving |
| Ranges (fraction of the sequence) | copy lift 0 to 0.25, console rise 0 to 0.38 (smoothstep), zoom 0.55 to 0.84, figure fade 0.68 to 0.84, overview reveal 0.86 to 1; copy lifts 72 px, overview rises 32 px and scales 0.94 to 1 |
| Scrolly step | border and text colour 240 ms ease-out |
| Reveal | 640 ms `cubic-bezier(0.2,0.7,0.2,1)`, opacity and a 24 px rise, once, observed at the lower 12 % of the screen |

## Trigger

Scroll position (one passive listener, one paint per animation frame, geometry measured on resize); reveal on the first time an element's top crosses the lower eighth of the screen.

## Reduced motion

Static page, top to bottom in DOM order: no pinning, no reveal hiding, step transitions off. Content is never hidden from reduced-motion users, from phones or from no-JavaScript visitors. Print forces everything visible.

## Dark theme

Colours are tokens (`--color-bg`, `--color-surface`, `--color-panel`, `--color-line`, `--color-accent-ink`), so the story switches with `html.dark`; the console artwork has dark variants.

## Do and don't

- Do reveal once; never replay on scroll back up.
- Do animate only transform and opacity, and set `will-change` only while moving.
- Do keep the static page as the default and add motion only when it fits.
- Do not reveal on hover.
- Do not hide content from reduced-motion users.
- Do not read layout on every scroll event (measure on resize).

## Copy-paste usage

```html
<link rel="stylesheet" href="scroll-reveal.css"><script src="scroll-reveal.js"></script>
<main id="page"><section data-reveal>…</section><section data-reveal>…</section></main>
<script>SwScroll.initReveal(document.getElementById("page"));</script>
```

For the pinned hero, build the `data-seq` structure shown in `demo.html` and call `SwScroll.initSequence(root)`.
